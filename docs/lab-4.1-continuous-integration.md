# Лабораторная работа 4.1: непрерывная интеграция

## Цель

Настроить автоматическую сборку и тестирование проекта при каждом изменении
исходного кода в основной ветке.

## Реализация в GitHub

Azure Pipelines заменён сервисом GitHub Actions. Определение конвейера хранится
в файле `.github/workflows/continuous-integration.yml` вместе с исходным кодом.

Конвейер запускается:

- автоматически при отправке исходного кода в ветку `main`;
- для запросов на слияние в `main`;
- вручную через вкладку **Actions**.

## Этапы конвейера

1. Получение исходного кода.
2. Установка .NET 10 SDK.
3. Восстановление зависимостей.
4. Сборка ASP.NET Core-приложения в конфигурации `Release`.
5. Выполнение автоматических тестов расчёта стоимости корзины.
6. Формирование сводки тестирования.
7. Публикация готового приложения.
8. Сохранение приложения и результатов тестов как артефактов на семь дней.

## Аналоги терминов Azure DevOps

| Azure DevOps | GitHub |
| --- | --- |
| Конвейер сборки | Workflow GitHub Actions |
| Агент | Runner / обработчик |
| Триггер непрерывной интеграции | Событие `push` |
| Переменные | `env` |
| История сборок | Workflow runs |
| Опубликованный артефакт | Actions artifact |

## Критерий успешного выполнения

Запуск **Непрерывная интеграция** должен завершиться зелёной отметкой. В его
сводке должны отображаться три пройденных теста, а в разделе **Artifacts** -
архивы `student-project-web` и `test-results`.
