# Лабораторная работа 4.0: обработчик сборочной линии

## Эквивалент Azure Pipelines в GitHub

Вместо агента Azure Pipelines используется обработчик GitHub Actions
(`runner`). Он получает задание, создаёт изолированную среду Windows и
выполняет шаги конвейера из YAML-файла.

Для учебного проекта выбран размещённый GitHub обработчик `windows-latest`.
Он не требует установки службы или хранения регистрационного токена на
локальном компьютере. GitHub создаёт чистую виртуальную машину для каждого
запуска и удаляет её после завершения задания.

## Настроенный конвейер

Файл `.github/workflows/runner-capabilities.yml` выполняет следующие действия:

1. запускается вручную или после изменения самого файла конвейера;
2. получает код репозитория;
3. определяет операционную систему и аппаратные характеристики обработчика;
4. проверяет наличие PowerShell, Git, .NET, Node.js, Python и Java;
5. публикует сведения в сводке запуска;
6. сохраняет текстовый отчёт как артефакт на семь дней.

## Возможности и требования

В Azure Pipelines используются возможности агента и требования конвейера.
В GitHub Actions их аналогами являются метки в параметре `runs-on`.
Значение `windows-latest` требует Windows-обработчик с актуальным набором
предустановленных средств разработки.

## Запуск

Откройте вкладку **Actions**, выберите **Проверка Windows-обработчика** и
нажмите **Run workflow**. Первый запуск также выполняется автоматически после
добавления файла конвейера в основную ветку.

Результат считается успешным, если задание **Проверка возможностей
обработчика** завершилось зелёной отметкой, а в разделе **Artifacts** доступен
файл `windows-runner-capabilities`.
