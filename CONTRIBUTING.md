# Правила совместной разработки

## Рабочий процесс

1. Выберите назначенную задачу в GitHub Project и уточните критерии приёмки.
2. Создайте ветку от актуальной `main`.
3. Выполните небольшое связанное изменение и добавьте тесты.
4. Создайте Pull Request и свяжите его с задачей через `Closes #номер`.
5. Дождитесь успешной автоматической проверки и ревью профильного участника.
6. После объединения проверьте обновление статуса задачи и поставки.

Прямые изменения в `main` не используются.

## Имена веток

- `feature/номер-краткое-название` — новая возможность;
- `fix/номер-краткое-название` — исправление ошибки;
- `test/номер-краткое-название` — тестирование;
- `docs/номер-краткое-название` — документация;
- `ci/номер-краткое-название` — автоматизация и инфраструктура.

Пример: `feature/7-checkout-api`.

## Коммиты

Сообщение должно кратко отвечать на вопрос «что изменено», например:

```text
Add cart total validation
```

Не объединяйте в одном коммите несвязанные исправления.

## Проверка перед Pull Request

```powershell
dotnet restore StudentProject.slnx
dotnet build StudentProject.slnx --configuration Release
dotnet run --project tests/StudentProject.Tests/StudentProject.Tests.csproj --configuration Release
```

## Критерии готовности

Задача считается завершённой, если:

- выполнены критерии приёмки;
- код прошёл ревью;
- автоматическая сборка и тесты успешны;
- документация обновлена;
- Pull Request объединён с `main`;
- связанная Issue закрыта.
